# 项目目录设计

## 设计目标

这个项目要同时满足黑客松的三个现实需求：

1. 分工要快：前端和模型可以并行推进
2. 演示要强：过程和结果都能讲清楚
3. 联调要稳：输入输出结构要尽早固定

所以整体采用“单仓双应用 + 共享契约”的结构：

- `apps/frontend`：负责交互和展示
- `apps/model`：负责实验和产出
- `shared`：负责前后端的数据契约

## 为什么不只分前端和模型两层

如果只有前端和模型两层，黑客松里很容易出现这些问题：

- 前端先写了一套字段，模型后面返回另一套字段
- 模型日志和结果没有统一结构，前端很难稳定展示
- 过程数据、中间指标、最终结果混在一起，后面很难讲故事

增加 `shared` 后，可以把“实验输入”和“实验输出”提早定死，让两边并行工作。

## 建议的输入输出边界

### 前端输入给模型

- 数据集信息
- 建模目标描述
- 提示词
- 运行配置

### 模型输出给前端

- 当前 run 信息
- 实验步骤过程
- 每轮实验状态
- 指标结果
- 最优方案摘要
- 导出物和报告地址

## 建议的协作节奏

1. 产品/前端先确定用户操作流
2. 共享层先定义输入输出 Schema
3. 前端用 mock 数据完成页面
4. 模型侧按 Schema 产出 JSON
5. 最后再做接口联调

## 当前原型怎么处理

根目录的 `model-navigator-v2.html` 可以继续作为演示稿和交互参考。

建议后续拆解为：

- 输入面板组件
- 过程流组件
- 结果卡片组件
- 部署交付组件

这样后面无论换 React、Vue，还是继续静态页面实现，都有清晰边界。
